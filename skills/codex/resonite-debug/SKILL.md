# Resonite Debug

For an unknown or changed port, run `resoloop discover --json`. It listens to official UDP 12512 announcements, usually every 10 seconds, with a default 12-second window; increase `--discovery-seconds` within 1..60 if necessary. An empty list does not prove Resonite is stopped. Check that the intended world's ResoniteLink is enabled and that announcements can reach this process; use an explicit URL when unavailable. `RESONITE_DISCOVERY_AMBIGUOUS` requires an exact session ID/name with `--url auto --session`, not the first candidate. Existing explicit URLs never fall back to another world. Local announcements map to localhost even when sent from this PC's LAN address.

`RESONITE_LINK_URL_MISSING` is a cue for the agent to discover automatically, not immediately hand port setup back to the user. Follow `resonite-build`'s automatic connection workflow: connect without extra confirmation for one candidate, ask the user to choose when multiple remain without an existing selection, and retry an empty result once before requesting missing information. Preserve any previously selected destination during failure recovery.

Strict apply validation performs adapter-side value conversion before asset import or mutation. For an old ambiguous checkpoint, adding manifest identityFields does not retroactively supply saved evidence; preserve state and inspect candidate IDs before a reviewed recovery. Current Blender exports avoid this by placing providers in separate named Slots. A Slot field drive inside the owned root should now be internal in item audit; check Slot `members` IDs for evidence. Do not move nested configuration into initialFields merely to suppress a diff: partial SyncObject comparison preserves omitted defaults while detecting drift in declared children.

When `item audit --allow-external-role` does not resolve an intended dependency, inspect `externalRoleCandidates` and `unmatchedExternalRoles` / `ITEM_ALLOW_ROLE_UNUSED`. Accepted selectors are a simple type name, namespace-qualified type, exact assembly-qualified type, or exact current component ID, followed by `:MemberPath`. Type selectors cover all matching components; ID selectors cover one session component. Review each target before allowing it; do not classify all material `_shader` references as safe. To investigate an enum, follow a reflected field with `type describe COMPONENT --member FIELD --json` instead of guessing its assembly or values.

Start with resoloop status --json. Use bounded hierarchy, find --under/--direct-children, inspect --component/--member, and component inspect to narrow the fault.

For UIX, use the `resonite-uix` skill and `uix audit VERIFIED_SLOT --depth 6 --max-slots 128 --json`. Computed size is reported as unknown; the audit is structural evidence, not a visibility test. A primitive reparent into a new empty Slot can leave an existing Image invisible: prepare the parent's RectTransform and layout first. Apply now orders relocation after parent preparation. `APPLY_COMPONENT_OWNERSHIP_CONFLICT` rejects overlapping live/deletion claims before mutation; inspect the reported IDs and use migrateFrom for an intentional key rename. For authorized temporary width/content/state checks, `set-members` probes preflight and restore all attempted field changes; `PROBE_RESTORE_FAILED` identifies unrestored targets. Capture and real-input checks remain separate.

Use type search and type describe to verify runtime names and member types instead of relying on memory. For an open generic, use type specialize with the exact assembly-prefixed search result. For ProtoGraph, run `flux validate-manifest` before live resolution, use flux node search/describe for exact full node identities, run flux check before flux build, fix error.context.primaryDiagnostics first, and use each diagnostic's channel when consulting raw stdout/stderr. `FLUX_EMPTY_MODULE`, `FLUX_MODULE_PORT_UNBOUND`, `FLUX_BINDING_TYPE_MISMATCH`, and `FLUX_INTERFACE_GLOBAL_UNSUPPORTED` are pre-deploy evidence, not generic SDK crashes. Flux scalar aliases such as `int`/`System.Int32` and `bool`/`System.Boolean` are equivalent; a mismatch after normalization is evidence of a genuinely different target type. For saved items, use item audit to distinguish broken external references from runtime-context dependencies. Use resoloop logs --tail 200 --json only when a log path is configured.

For multiplayer-only faults, inventory every entrypoint's processing user and every mutable value's scope before changing the graph. `LocalUpdate` fires for every user, `LocalUser` identifies the current executor, `Local` is impulse-context state, `Store` is per-user non-networked state, and data-model fields or `Data Model Store` are normally synchronized. Look for per-user triggers contending on one synchronized field, an ambiguous listener/update user, high-frequency writes that should remain local, or a host gate that accidentally selects a headless host. Distinguish ProtoFlux `Drive` from synchronization and from manifest binding `mode: drive`. A successful single-user test does not rule out these faults; reproduce with at least two users when authorized, otherwise report the multiplayer hypothesis and verification gap.

`STABLE_COMPONENT_AMBIGUOUS` means the saved type/member/index evidence was insufficient; add an immutable `identityFields` value or a stable managed reference instead of choosing an ordinal by guess. For an equipped tool, `APPLY_RUNTIME_RELOCATABLE_ACTIVE` is a safety stop rather than a missing target: use its stable selector for read-only inspection, run `tool audit` when the whole item tree is observable, and return/drop it to the declared parent before apply. `STABLE_RELOCATABLE_SLOT_AMBIGUOUS` requires stronger same-Slot Component identity evidence; never pick a candidate by name alone. `SKILL_SYNC_CONFLICT` protects a user-edited or untrusted project skill and must be reconciled rather than overwritten.

`APPLY_LIST_SHRINK_REFERENCED` stops a list-shrink recreate before mutation because something in the hierarchy apply read, other than a managed declared reference, points at the Component; declare that reference with a stable selector or remove it. `APPLY_LIST_SHRINK_NOT_CONVERGED` means the replacement list did not converge before the old Component could be safely removed. Apply undoes only replacements whose original Components remain and whose removal would not break references; others stay in progress in the checkpoint. Follow the error's `recovery` and `inProgress` instead of blindly retrying an unchanged declaration. `APPLY_RECREATE_INTERRUPTED` means an interrupted recreate cannot resume automatically; follow the suggestions for its `reason` and never pick a candidate by position.

Explain the evidence and root cause. Do not mutate the world during a diagnosis-only request. If a fix is requested, make the smallest scoped change, re-inspect, and confirm the observed result.

For UIX image placeholders, follow `resonite-uix/references/assets.md`: correlate source pixels, exact URL/variant logs and a controlled comparison before blaming compression. `APPLY_REFERENCE_NOT_RETAINED` requires inspecting an existing driver owner; a write response alone does not prove the target retained a reference. `APPLY_SLOT_OWNERSHIP_CONFLICT` means live and stale keys claim one Slot; stop and resolve identity rather than pruning through it. `APPLY_STATE_BUSY` means another apply holds this checkpoint's writer lock; wait and retry, and never delete a lock file to bypass an active writer. Read-only observations can share complete checkpoint snapshots, but they do not make the changing world transactional. `REFERENCE_VALUE_QUOTED` indicates literal quote characters reached a reference ID; keep shell quoting outside the value.
