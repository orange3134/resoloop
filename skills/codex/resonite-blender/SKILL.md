# Resonite Blender

Use Blender when the requested silhouette, organic surface, cutouts, bevels or topology would be awkward or expensive to build with Resonite procedural meshes. Prefer native meshes for simple or runtime-parametric shapes. Combine an authored mesh with native colliders, interaction and Flux where useful. Preserve the requested visual quality and scope.

## Find Blender before modeling

Run `resoloop blender find --json` (no Resonite connection required). It executes `--version` after discovery. Selection order is explicit configuration, PATH, standard install folders, then Windows App Paths / uninstall registry. Standard Windows discovery includes versioned folders under Program Files/Blender Foundation and per-user Programs; PATH need not contain Blender. With several versions, explicit configuration is reproducible; the standard-folder scan prefers the highest version within a root.

Override with `--blender-executable "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe"`, `RESOLOOP_BLENDER_EXECUTABLE`, or `blenderExecutable` in `.resoloop.json`. Configuration precedence is CLI > environment > project > user. An invalid explicit path fails instead of silently selecting a different version. Treat the example version/path as an example, not a universal installation location.

If discovery fails, check a user-supplied path and bounded likely portable/Steam install locations (Steam library folders may be on another drive). Do not recursively scan entire drives or edit PATH. If Blender is absent, ask the user whether it may be installed before downloading/installing, unless that installation is already authorized. The CLI does not install Blender. Use an existing installation when available; a missing optional Blender tool does not block native-mesh work.

## Author for real-time VR

Keep a reproducible `model.py`, editable `.blend`, exported bundle and resource report in the project. Establish the requested visual quality, physical size, viewing distance and expected simultaneous instance count. First develop the silhouette, layered construction, focal mechanisms, curved surfaces and convincing material detail. Use enough geometry for the intended close-up appearance; a hero vehicle, ship or landmark can justify substantially denser meshes than a small repeated prop. Stylization simplifies visual language, not necessarily geometry or craftsmanship. Surface relief, gaps, rims and fittings that benefit from parallax, shadows or close viewing may remain geometry even when they do not alter the distant silhouette. Bake fine surface detail where it preserves the intended appearance.

There is no universal low-poly target, material quota or texture-size ceiling for this workflow. Choose resources for the asset's role and on-screen detail; do not force every model into one material or a small shared atlas if that sacrifices material separation, unique wear or texel density. Larger textures and additional materials are appropriate when they visibly improve the result. After reviewing the visual result, remove invisible or redundant work and assess aggregate cost across instances, expanded vertices, draw sections, texture memory with mipmaps, alpha overdraw, shadows and colliders. Preserve UV seams, intentional hard edges and visible detail during optimization. Use resource sharing, simple colliders or LOD where useful. Do not decimate or halve geometry merely to reach a round number or clear a warning. The exporter's current thresholds (50k triangles, 8 materials, 16 draw sections, 2048px) are advisory review triggers, not maximum budgets, errors or evidence of poor runtime performance. Record why a resource cost is justified; investigate measured bottlenecks when available instead of lowering quality speculatively.

Review at three distances: distant silhouette, medium-distance structure/material separation, then close-up edges, grain and wear. Compare with the user's visual direction or concept images when available. If broad forms look like assembled primitives or focal areas feel sparse, add designed transitions, depth, fittings and material variation before calling the model finished. Concentrate detail on focal areas and avoid uniformly strong procedural noise. Use smooth normals on curved surfaces and intentional hard edges at real creases; inspect the result before adding Edge Split or applying blanket smoothing. UV seams, flat faces and tangent discontinuities expand runtime vertices even when triangle counts stay constant. Compare visual quality as well as both counts between revisions; keep a more detailed source before reduction. Import success and low resource counts alone do not establish artistic quality, and more polygons alone do not fix weak design, UVs, materials or lighting.

For concept-led production, compare actual Resonite views with the chosen concept during blockout and after the main assets, before filling the scene with props. Check space proportions, openings, focal shapes, material response and the distribution of detail. Preserve the approved direction instead of silently simplifying it into a different visual style. Record meaningful departures and resolve the ones that weaken the requested appearance. Review resource totals by module alongside its visible contribution; repeated floor stones or roofing should not consume most of the effort while focal equipment remains generic. Higher polygon counts and longer prop lists are not evidence that the concept has been realized.

Run Python in background:

```powershell
resoloop blender run modeling/model.py --arg=artifacts/prop.blend --json
# Load a source file before executing a modification script:
resoloop blender run modeling/adjust.py --blend artifacts/prop.blend --arg=artifacts/prop-v2.blend --json
```

Use repeated `--arg=VALUE`; for a Python flag use e.g. `--arg=--output`. The script reads arguments after `sys.argv.index("--")`. resoloop orders `--background --factory-startup --disable-autoexec [FILE.blend] --python-exit-code 1 --python SCRIPT -- ...`; spaces are passed as arguments, not shell code. `--command-timeout` limits the whole process and kills its process tree on cancellation. Explicit Python runs with the caller's filesystem permissions; keep its outputs in the project and inspect unfamiliar scripts. Check the installed Blender's Python RNA/API before using version-sensitive operations.

Do not render a final image as part of model production. Prefer topology/material statistics and Resonite inspection. If a temporary Blender render helps resolve a visual question, keep it to a small preview (for example 512–768px, Eevee or low samples); stop once that question is answered. Baking required texture detail is separate from producing a high-quality final render, and still needs a bounded resolution/sample budget.

For thousands of repeated parts, prefer direct mesh/datablock construction and batch operations over per-part context changes and `bpy.ops` calls. Keep editable source modules before consolidating runtime meshes, and preserve separate pivots for moving parts. Profile slow construction steps before simplifying visible shapes. Use stable names, explicit random seeds and iteration order in rebuild scripts. Verify both same-manifest reapply and source regeneration: tiny UV changes from modeling/modifier evaluation can change tangents, vertex splits and asset hashes. Do not round away UV seams or ignore changed mesh files to force a no-op.

## Export an importable bundle

Save generated/edited image pixels before saving the `.blend`. For portable source files, reload the saved image while preserving its color space and pack it, then save and reopen the `.blend` to verify pixels and paths. Set Non-Color before filling/saving normal or packed data maps. Saving a `.blend` alone is not a reliable substitute for saving edited external image buffers. The exporter saves available current pixels directly (Blender `Image.copy()` does not copy edited buffers); if a buffer is unavailable, it may recover only from the image's recorded existing file and reports a warning. It cannot recover lost unsaved pixels. A missing-image error includes the image name/path; fix that source rather than dropping the texture.

Packing does not keep an otherwise unused image datablock in a saved file. Retain required unconnected source maps with `use_fake_user=True` (or an actual user), then verify their presence and pixels after reopening.

Unused material datablocks also need an actual user or `use_fake_user=True` when later scripts depend on them. Reopen the saved source and check required materials as well as images. New extension meshes that use image materials need their own UVs; a successful earlier export does not validate newly added geometry.

```powershell
resoloop blender export artifacts/prop.blend --output content/prop-v1 --name Prop --parent VERIFIED_PARENT --json
# Optional: limit export to a named collection and its descendants with --collection Prop
# Preserve authored object origins/parents and pack supported PBR data images:
resoloop blender export artifacts/prop.blend --output content/prop-v2 --name Prop --parent VERIFIED_PARENT --preserve-hierarchy --pack-pbr --json
```

This command is offline and does not mutate Resonite. It exports visible mesh objects in the current scene/view layer (or specified collection), ignoring cameras/lights. Use a dedicated collection to avoid accidental extra geometry. Output must be a new directory; failed bundles are incomplete and must not be applied. Preserve an existing apply/state ownership key and object/material names across revisions, and use the same explicit `--state` for reapply. The exporter flattens static object hierarchy and bakes world transforms into mesh vertices; the bundle root is the shared origin. Set that origin intentionally in Blender. Scene `scale_length` is applied as metres. Do not scale the imported model a second time accidentally.

For parts that need independent pivots, use `--preserve-hierarchy`: it retains parent transforms and local mesh coordinates, including ancestor transform Slots. Shear, singular transforms and animated/constrained ancestors require an explicit static adaptation. This is a static hierarchy, not animation export. When adding native drivers, avoid managing their continuously changing transforms on every apply; put a fixed placement Slot above the driven Slot if needed.

Use `$slot-member:drivenSlotKey.Rotation` (or another exposed Slot field) for a native driver's target field reference. `$member:componentKey.MemberName` refers to a Component, not a Slot. Reflect the driver's actual target member before declaring it, run strict validation and verify the observed field ID and time-varying value after apply. Do not rely on a driver's automatic target hookup as proof that it drives the intended Slot. These selectors supply references; they do not make Slot fields writable through Component set-member probes.

New exports put each material/texture provider in a unique named Slot under `Blender_Providers`, so it can be re-identified before reference wiring completes after an interruption. For an existing root-provider bundle, use `--legacy-root-providers` to preserve that layout; inspect any hierarchy/layout migration in diff before applying. Do not silently switch modes on an existing state. Old ambiguous checkpoints are not repaired merely by adding identityFields to the manifest: preserve the checkpoint, inspect exact candidates and ownership, and use explicit reviewed recovery rather than guessing by index or blindly adopting.

The bundle contains `model.apply.json`, `*.mesh.json`, copied PNG textures and `report.json`. Read the report and review the apply before import. It supports:

- Evaluated mesh modifiers, triangulation, split corner normals, UV seams, tangent vectors/signs and active vertex colors. Vertices are shared only when all exported attributes match. The render-active UV map is channel 0; remaining UV maps follow it consistently for every vertex. Vertex colors are preserved as mesh data but need a Reflection-verified material that actually uses them; PBS_Metallic does not automatically display them.
- Blender world `(x,y,z)` -> Resonite `(x,z,y)`, with mirrored-object winding correction and inverse-transpose normal conversion for nonuniform scale. UV coordinates are not flipped. Tangent handedness changes with the coordinate transform. Validate with an asymmetric colored/textured front face, not a symmetric untextured cube.
- One submesh per used material, with `MeshRenderer.Materials` ordered to match submeshes. Shared Blender materials/images become shared providers inside the owned root; mesh and texture asset URLs are referenced through `$asset`, then connected via `$component` references.
- Opaque Principled BSDF -> PBS_Metallic: constant base color, metallic and roughness (`Smoothness = 1 - Roughness`), direct sRGB base-color/emission images, constant emission strength, and Non-Color tangent-space normal images through a Normal Map node. Linear Blender socket colors are converted to the CLI colorX tuple's runtime sRGB values; do not gamma-convert color images again. Normal textures get `IsNormalMap=true`; mipmaps are enabled. Use Flat/Repeat/Linear Image Texture sampling, with unlinked Vector (active UV).

Unsupported node graphs fail instead of silently dropping important inputs. Procedural textures, Mapping nodes, Bump, linked metallic/roughness, transparency, coat/transmission/subsurface and other specialized shaders require intentional baking/material adaptation. Realize Geometry Nodes/collection instances and convert curves into an explicit mesh copy first. Rigs, shape keys and animations are outside this static exporter; do not promise preserved animation or freeze an animated asset without the user's intent. Keep the original `.blend` for unsupported features.

With `--pack-pbr`, direct Metallic/Roughness Image Texture inputs are supported: Non-Color still images, Flat/Repeat/Linear sampling, the active UV with unlinked Vector, and matching dimensions. Use grayscale Color or Alpha for a scalar; arbitrary RGB-to-value conversions are rejected. An unlinked input retains its constant value. The exporter packs R=metallic, G=1, B=0, A=1−roughness and sets the data provider's `PreferredProfile` to `Linear`. It does not silently resample, change UVs or bake arbitrary graphs. Run strict validation before apply; it now checks write conversion, including nullable enum values, without importing assets.

UV-bearing n-gons are triangulated in a temporary mesh before tangent calculation while preserving corner data; no workaround Triangulate modifier is required. This preserves the evaluated shape and shading, and does not optimize topology automatically.

For a richer baked material, export the supported base, place maps beside the bundle, add `kind: texture` assets and StaticTexture2D providers to the apply, then bind Reflection-verified members. Base PBS_Metallic packing is R=metallic, G=occlusion or height, A=smoothness (1−roughness); glTF ORM uses a different layout and cannot be plugged in unchanged. Use a linear/Non-Color profile for data maps, verify the runtime `PreferredProfile` enum, and reuse a packed provider for `MetallicMap` / `OcclusionMap` when appropriate. Albedo/emission are color images; normal maps use OpenGL normals. Do not treat arbitrary Blender shader graphs or UDIMs as transferable. Check the target shader's channel convention rather than generalizing base PBS_Metallic to every shader.

Use `resoloop type describe FrooxEngine.StaticTexture2D --member PreferredProfile --json` to obtain the field's exact reflected type and enum values, including its assembly. Do not guess the assembly or numeric enum value. `--member` unwraps a reflected Nullable value type. After manually adding textures/materials or changing geometry in the exported apply, recount the final bundle's resources and record them in the delivery report: exporter `report.json` describes export time and does not automatically track subsequent edits.

## Import and verify through ResoniteLink

The pinned ResoniteLink 0.13.1 exposes mesh/texture asset import, not a whole `.blend`/FBX/GLB scene importer. A mesh asset URL alone does not instantiate a renderer or materials. Do not send GLB to `kind: mesh` or invent a model-file import message.

The saved mesh uses ImportMeshJSON schema (vector objects, UV `{"$type":"2D","uv":{"x":0,"y":0}}`, submesh `{"$type":"trianglesFlat","vertexIndices":[0,1,2]}`). resoloop validates it and converts uniform static mesh data to the public `ImportMeshRawData` API. This preserves UV channel dimensions and avoids the live JSON import error `UV channel 0 is already configured with 0 dimensions`, while reducing transport size. Do not remove UVs to bypass this error. Bone/blendshape or nonuniform optional-attribute data remains outside that binary conversion; the static Blender exporter emits uniform data.

Mesh bytes are sent by the client; `ImportTexture2DFile` reads a path on the Resonite host. The normal workflow assumes Blender/CLI/Resonite on the same computer. For a remote host, use an authorized shared path accessible at the same absolute path to both CLI (hashing) and Resonite (import), or run the CLI on that host. Merely changing source to an inaccessible remote path cannot upload it. Keep source images until imports complete. Treat returned `local://` or `resdb://` URLs as opaque; do not invent URLs or assume import proves durable upload/storage.

1. Run `resoloop status --json`; observe a bounded hierarchy and inspect the intended parent in the current session. Follow `resonite-build` ownership and exact-target safety. Before using unfamiliar members, run `type search` / `type describe` for StaticMesh, StaticTexture2D, MeshRenderer and the chosen material. `--parent` in offline export does not verify its target.
2. Run `validate FILE --json`, `validate FILE --strict --json`, then `diff FILE --changes-only --json`. Check owned root, mesh/texture sources, material ordering, resource report and desired scale. Only apply within the user's requested scope; do not use adoption to bypass an ambiguous target.
3. Run `apply FILE --state STATE --json`, retain the state checkpoint, inspect the created Slots and asset/material references. Reapply with the same state and confirm no redundant writes/imports. Do not discard state on timeout; check progress before increasing request/command timeout.
4. Capture a modest actual Resonite image with the project's camera bookmark, inspect front/back visibility, UV orientation, seams, normal-map lighting, texture color, scale and material assignment. Asset integration can complete after the import response, so allow a bounded wait before deciding a material is missing. An asset URL and structural check alone do not verify appearance. Blender final rendering is unnecessary.
5. Verify the requested interactive behavior in Resonite and portable closure with `item audit` where relevant. Record resources attributable to this model: triangles, expanded vertices, meshes, materials, draw sections, texture dimensions and estimated memory, plus added lights and driving Components. Draw sections and memory estimates are structural estimates, not measured frame cost. Do not measure session FPS to judge an individual model or list FPS testing as pending: user count, other items and ongoing world edits confound it. For experiments create `ResoLoop_Test_*`; in `finally`, re-inspect and delete only that exact verified Slot with explicit `--yes`. Never clean Root or unrelated user content. Keep required visual, behavioral or portability checks marked pending when not performed.

For external dependencies, inspect `issues` and `externalRoleCandidates` before using `--allow-external-role`. Prefer the exact reported `[Assembly]Namespace.Type:MemberPath` for a reviewed type-wide policy, or `COMPONENT_ID:MemberPath` for just one current-session component. The latter is not portable across sessions. Check `unmatchedExternalRoles` / `ITEM_ALLOW_ROLE_UNUSED` to catch ineffective allow entries. Never auto-allow `_shader` merely because a material has that field; inspect the target. A non-strict audit with warnings does not prove saved/reloaded portability or interactive usability.
