# Resonite Inspect

For investigation or cross-platform porting of already imported content, start offline with `bundle summary BUNDLE`, `bundle tree BUNDLE --depth 3`, and `bundle find BUNDLE --name/--type/--text QUERY`. Use exact returned keys for `bundle inspect --key KEY` and `bundle refs --key KEY --direction in|out|both --depth 2`. Incoming member references can identify recorded writers/drivers without live reads; names alone do not prove dynamic-variable bindings. Preserve false/zero/null and Enabled/IsActive; do not strip them from simplified views. Use --member or structured --member-path for large containers. Follow nextOffset with --offset, bounded --limit/--max-bytes, and retain source file/JSON Pointer/hash/time evidence. Names/paths are descriptive and may collide. These commands read captured observations, not pending edits or live runtime state.

If needed external data is identity-only or unresolved, use `bundle collect-dependencies BUNDLE` only against the verified original world session, with explicit depth/object/byte/time budgets. After restart, re-import first. It saves a separate dependencies.capture.json (or a new --output file selected later with --dependencies); never edit snapshot hashes or enroll dependencies for writes. The collector does not traverse Root, Slot parents/children or attached Components implicitly, and never downloads asset bytes. Opaque/error/limit statuses must be retained as unknowns, not called dangling references. Original and dependency captures have different timestamps. Use `bundle extract --under SLOT_KEY --include-dependencies --depth N --output NEW_FILE` for a bounded evidence excerpt, and inspect its unresolved boundary list. Do not pass analysis excerpts to apply. See docs/BUNDLE-ANALYSIS.md.

When asked to register an existing subtree without altering it, first observe the exact boundary, then use `import SLOT --output NEW_DIRECTORY`. Import reads in bounded-depth batches (with an explicit Slot-count ceiling), records all exposed member data plus runtime Reflection capabilities, and rechecks structure before publishing. It adds no tags, renames nothing, and never invokes mutation APIs. Read the local report and snapshot selectively rather than dumping the whole graph. `diff manifest.json --summary --profile --report NEW_FILE.json` verifies an empty edit set has zero changes; report warnings identify observation-only types or lost bindings. This compares explicit edit intent, not every changing runtime value. Preserve the snapshot and state. A world-session change requires fresh observation/re-import, not ID reuse or matching duplicate siblings by order. Imported component keys belong to their bundle and are edited through `existing.changes`; their state file is not interchangeable with generated-content stable-selector state.

P1 snapshots also contain reference edges and external dependencies, either in the single snapshot or its indexed parts. Count external dependencies separately from owned Slots/Components. Each reference has a bundle-local key and a structured source path; member target paths preserve literal names, indices and dictionary keys. Do not split names on dots or infer identities from array positions. Readable external Component/Slot targets carry observed identity/type evidence; opaque targets remain recorded without claiming they are dangling. An empty edit set preserves every reference. To verify explicit retention, copy selected observed targets into `existing.referenceChanges` and run read-only diff; do not apply that verification manifest to user content. P0 snapshots remain readable, but need a new import directory to acquire a P1 reference graph. Keep external reads bounded to the captured IDs; do not scan unrelated world content to guess their owners.

For split import use `--split-slots 256`, inspect the schema-3 index and relevant hashed parts selectively, and retain every part plus the common state. Keys resolve across all files within one import; do not mix independent bundles or infer precedence from file order. `existing.editFiles` may separate explicit intents while retaining common ownership/snapshot identity. `slotChanges` manages only requested local transforms, activation/persistence, Tag and OrderOffset; an empty set must still produce zero changes even when live values evolve. Inspect Slot member IDs/types before any proposed edit; an unset Tag may be null, while empty text is its clear intent. Read-only verification must not send these observations back as an apply request. See `docs/EXISTING-BUNDLES-SLOTS.md` for the file contract.

For several known Reflection requirements, use `type query --request FILE.json --json`; get the shape from `schema describe reflection --json`. Select explicit members, including reference target types; add `enums` only where candidates are needed. Version-matched disk metadata is trusted (`verified: true`, `source: version-cache`, original `observedAt`), including after restart or a local port change. Use `--refresh` after MOD/DLL changes or `--cache off` for live-only evidence. `type check --request FILE.json --brief --json` returns a compact contract verdict and structured differences; it uses the same cache unless refresh/off is requested. These commands never write world content. Search/describe remains appropriate for unknown names or full definitions. Type caching never validates an old instance ID, value or reference target.

For several known managed fields, use one `observe '$member:KEY.FIELD' [...] --state STATE --json` (1..64 selectors). Output retains Component/member IDs, types, values and reference targets; missing members fail instead of producing partial success. Each selected Component is read once per invocation. Cross-Component reads are sequential, not atomic; nested/list member payload sizes are not capped by the selector limit. Use structural inspect or Reflection when the needed member names are not yet known.

If no connection URL is configured in CLI/environment/project/user settings, run `resoloop discover --json` yourself (12-second announcement window) before asking the user for a port. One candidate: connect without an extra permission question and identify the selected session. Multiple candidates: honor an existing user selection; otherwise present names and URLs and ask the user which session to inspect, waiting for their answer. Zero candidates: retry once with `--discovery-seconds 20`, then ask for ResoniteLink to be enabled or for its current URL. Reuse the selected URL explicitly for later commands, preserve existing configuration, and re-observe after connecting. Discovery session IDs identify world sessions and are distinct from the connection-scoped ID in status; neither substitutes for a current Slot/Component observation. See `resonite-build` for the shared automatic connection workflow.

Use --json. Confirm connection, then start with `hierarchy --depth 1 --summary --include-components --json` for IDs, names, types and reference-only boundaries without field payloads. Scope with `--under` and the appropriate `--state` for managed selectors. A finite depth does not bound a wide hierarchy's child count; prefer find --name or --component scoped with --under and --direct-children. For member evidence, use inspect --component TYPE --member NAME, which returns a flat counted component view, instead of dumping a deep world with --members. Use --exclude-reference-only when generated references are irrelevant.

Use IDs from the active session for immediate follow-up commands. For managed content after reconnect, prefer `$slot:key` or `$component:key` with the exact apply `--state` file; resoloop re-resolves path, identity fields, managed reference topology, and member identity instead of trusting a stale raw ID. Use component list and component inspect only for relevant targets. If a type or field is unclear, use type search followed by type describe; do not infer names.

For literal slashes/backslashes or surrounding spaces in a Slot name, use an exact name-array selector, for example PowerShell `resoloop slot inspect 'path:["Root","A/B"," Label "]' --json`. Plain slash paths remain hierarchy syntax. Checkpoint schema 2 stores exact name segments; display paths alone can collide. Do not normalize or rename user content merely to inspect it.

For a field's value type or enum values, use `type describe COMPONENT --member FIELD --json`, for example `FrooxEngine.StaticTexture2D --member PreferredProfile`. It follows the exact reflected valueType and unwraps Nullable; non-component types may need an assembly-qualified name and are not discoverable through component search. Do not guess enum numbers or assemblies. References without a valueType require inspection of their target metadata instead.

Slot inspection includes public Slot `members` and their current-session IDs (Position, Rotation, etc.). Use these observed IDs to identify field ownership; do not infer owner IDs arithmetically. Item audit counts fields of Slots inside the inspected root as internal targets. Scene summary reports `bounds.kind`: `geometry` uses known geometry, `partial` has missing renderer extents, and `pivots` encloses origins only. These are declaration/rest bounds, not animated swept bounds. Live capture returns `ownership` with its temporary Slot parent/ID/name and cleanup result; camera creation currently uses Root.

Return the important Slot path, IDs, transforms, Components, and member evidence. Do not edit or delete content.
